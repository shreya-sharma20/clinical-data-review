# ADaM Dataset Explorer requirements

Each requirement is testable and is mapped to at least one test in `TESTS.md`.
The R package is named `adamreview`; "ADaM Dataset Explorer" is the
user-facing name (REQ-14).

## Explorer

- **REQ-01** The app shall load a demo ADaM dataset (ADSL or ADAE from
  `pharmaverseadam`) by name and return the data together with per-variable
  metadata (name, label, type). An unknown dataset name shall produce a clear
  error.
- **REQ-02** The app shall read an uploaded XPT or CSV file into the same
  data-plus-metadata structure as REQ-01. A missing file or an unsupported
  file extension shall produce a clear error rather than a crash.
- **REQ-03** The app shall summarise a dataset in one table per variable
  type, each containing only columns that apply to that type, and shall only
  return the tables for types that are present: numeric variables (n, missing,
  mean, sd, median, min, max); categorical variables, i.e. character, factor
  and logical (n, missing, distinct, most frequent value, its count and its
  percentage); and date variables (n, missing, earliest, latest). Empty
  strings count as missing for character variables. It shall also give a
  one-line overview of the dataset (rows, columns, percentage of missing
  cells).
- **REQ-04** The Explorer shall have three tabs, in this order, that follow
  the loaded dataset (demo or upload). **Data** is shown first and has a
  "Data Preview" header with the one-line overview, a filterable table, and an
  (i) button that opens a searchable pop-up with each variable's name, label
  and type. **Summary** shows the tables of REQ-03, each under its own heading
  and only for the types present. **Charts** is described in REQ-10 to REQ-12.

## Compare

- **REQ-05** The app shall compare two datasets with `diffdf::diffdf()` and
  return a tidy table with one row per difference (issue type, variable,
  detail). Identical datasets shall return an explicit "identical" result
  rather than an empty or ambiguous table.
- **REQ-06** The comparison shall detect and report differing values, columns
  present in only one dataset, differing row counts, and type (class)
  mismatches between the two datasets.
- **REQ-07** The Compare tab shall let the user supply two datasets (upload),
  run the comparison on demand via a button, and show the resulting diff table.

*REQ-08 (a downloadable Quarto report) was withdrawn when the Report feature
was removed; the number is left unused so the other requirement ids stay stable.*

## Charts (Explorer)

- **REQ-10** The app shall build four fixed interactive plotly charts from a
  data frame: missing values by variable (horizontal bars, most incomplete
  first, capped at 20 bars for wide data); the composition of a categorical variable (a
  donut of the most frequent categories, the rest pooled into "Other");
  the distribution of a numeric variable (a histogram, optionally split by a
  group variable); and a numeric variable by category (a box plot). Axis
  titles shall show the variable label, falling back to the variable name. The
  app shall list the variables offered in the pickers: numeric variables with
  at least one value, and low-cardinality categorical variables (identifiers
  and all-missing variables excluded).
- **REQ-11** Grouping and categories shall label missing values "(Missing)" and
  pool rarely occurring groups into "Other". All-missing variables, zero-row
  data, data without missing values, and datasets without any suitable
  numeric or categorical variable shall produce an empty chart carrying a
  message rather than an error; unknown columns and variables of the wrong
  type shall produce a clear error.
- **REQ-12** The Charts tab shall show the four charts of REQ-10 in panels.
  The variable pickers shall follow the currently loaded dataset (demo or
  upload) and the charts shall render.

## Sample data

- **REQ-13** The repository shall ship reproducible, fully synthetic sample
  datasets as both CSV and XPT (XPT with variable labels), generated by
  `data-raw/make_sample_data.R` with a fixed seed: an ADSL of about 60
  subjects, a linked ADAE, deliberately modified copies for Compare (ADSL with
  changed values, a dropped column, an added column, removed rows and a type
  change; an unchanged ADSL copy; a modified ADAE with a renamed column and
  extra rows; a rounded ADSL; a re-sorted ADSL) and an edge-case dataset. Every
  file shall load through the app's loader, and each modified copy shall give
  the differences it is documented to give when compared.

## Naming

- **REQ-14** The user-facing name of the app shall be "ADaM Dataset Explorer"
  (application title), while the R package keeps the name
  `adamreview`.

## Architecture (applies to all phases)

- **REQ-09** All work (loading, summarising, charting, comparing) shall live in
  plain `R/fct_*.R` / `R/utils_*.R` functions with no `input`/`output`/`session`
  arguments; `app_server.R` shall contain only `mod_*_server()` wiring.
